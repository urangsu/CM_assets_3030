# CM_assets_3030: Tab Quality Audit & P0 Stabilization Report

## 목적
현재 React + Vite 기반 로컬 우선 예산관리 앱(`CM_assets_3030`)에 대해 각 탭에서 실무 사용상 발생할 수 있는 데이터 오염, 숫자 오해, 권한 관련 치명적 오류를 제거하고 그 결과를 기록합니다.

## 점검 및 조치 내역

### 1. 예산 초과 점검 (`BudgetOverrunCheck.tsx`)
- **초과월 관련 필드 신설:** 초과월, 초과월수, 최대초과월, 월별초과내역 컬럼을 추가했습니다.
- **월별 상세 확장 기능 (Accordion):** 각 행(부서/계정) 클릭 시 월별 예산 vs. 집행 현황을 상세히 조회할 수 있도록 Table 확장(Accordion) 기능을 추가하였습니다.
- **필터링 점검:** "인건비 제외" 및 "인건비만 보기" 필터 기능을 활성화하여 `budgetAggregation.ts`의 `isSalaryAccountCode` 유틸을 연동시켰습니다.
- **엑셀 다운로드 포맷 보강:** 메인 시트 외에 `월별상세` 시트를 새로 구성하여 배포 실무에서 오프라인 분석이 용이하도록 보완했습니다.

### 2. 권한 및 집계 로직 (`permissions.ts`, `budgetAggregation.ts`)
- **권한 유틸 단일화:** 사용자의 부서(deptCode)가 아닌 `user.code` 기준으로 판단하도록 `getUserCode`, `getPermissionContext` 등을 통일했습니다. 
- **인건비 열람 권한 제어:** `user.code`가 `32100` (기획재무그룹) 또는 `99999` 인 경우, 혹은 관리자 패널에서 인건비 열람 권한을 직접 부여받은 경우에만 인건비 내역이 표시되도록 구조화했습니다.
- **기간 파싱 (parsePeriodMonth):** 'N월', '2026.01' 등의 문자열을 안전하게 인덱스로 매핑할 수 있도록, 실패 시 `0`이 아닌 `null`을 반환하도록 설계하여 집계 시 null 기간은 배제합니다.

### 3. 예산 작성 (`BudgetCreation.tsx`)
- **데이터 오염 차단:** 관리부서 권한(All)으로 조회 시 0원인 값을 1원으로 임의 치환하던 버그(mocking 로직)를 완전히 제거하여 예산 데이터의 원본성을 보증합니다. 필터링 로직 또한 전부 0인 계정을 판별하도록 교정했습니다.
- **제출(Submission) 구조 통일:** 제출 상태 저장 로직을 여러 개별 키에 파편화시키지 않고, `cleanmetal_submission_status` 라는 단일 키명 하위에 Dictionary 형태로 관리(`deptCode_year_planType`)하도록 통합 및 마이그레이션을 구현했습니다.

### 4. 실적 및 경영계획 데이터 업로드 (`PlanActualUpload.tsx`)
- **파싱 실패 및 Validation 강화:** 사용자가 기간 형식을 잘못 입력할 경우 (예: 'xx월' 등) `parsePeriodMonth`가 null을 반환함을 감지하고, 저장 전에 오류 목록 모달을 띄워 잘못된 행 번호와 원본 값을 안내하도록 UX를 안정화했습니다.

### 5. 업무활동경비 (`BusinessActivityBudget.tsx`)
- **Mock / Random 데이터 제거:** `normalizeHeadcounts` 등의 유틸로 순수 엑셀 형태나 JSON 객체 구조의 헤드카운트만 읽어 들이며, `Math.random()` 등으로 무작위 데이터를 발생시키던 더미 코드 잔재가 없음을 검증 및 정리 완료했습니다.

## 결론
이번 P0 안정화 패치로 모든 탭에서 실무상 데이터 오염 포인트가 차단되었으며, 특히 예산초과 점검 탭에서 디테일한 월별 추적이 가능해져 설계 리뷰 기반 정리가 완료되었습니다. 이후 대시보드 고도화, 계정 및 부서별 현황 고도화를 위한 기반이 견고해졌습니다.
