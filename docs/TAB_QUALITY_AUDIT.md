# CM_assets_3030: Tab Quality Audit & P0 Stabilization Report

## 목적
현재 React + Vite 기반 로컬 우선 예산관리 앱(`CM_assets_3030`)에 대해 각 탭에서 실무 사용상 발생할 수 있는 데이터 오염, 숫자 오해, 권한 관련 치명적 오류를 제거하고 그 결과를 기록합니다.

## 점검 및 조치 내역

### 1. 예산 초과 점검 (`BudgetOverrunCheck.tsx`)
- **초과월 관련 필드 신설:** 초과월, 초과월수, 최대초과월, 월별초과내역 컬럼을 추가했습니다.
- **초과월 표시 포맷 정비:** 배열로 저장된 숫자를 그대로 표시하지 않고 '2월, 3월'과 같은 규격화된 포맷을 적용하여 식별성을 개선했습니다.
- **월별 상세 확장 기능 (Accordion):** 각 행(부서/계정) 클릭 시 월별 예산 vs. 집행 현황을 상세히 조회할 수 있도록 Table 확장(Accordion) 기능을 추가하였습니다.
- **필터링 점검:** "인건비 제외" 및 "인건비만 보기" 필터 기능을 활성화하여 `budgetAggregation.ts`의 `isSalaryAccountCode` 유틸을 연동시켰습니다.
- **엑셀 다운로드 포맷 보강:** 메인 시트 외에 `월별상세` 시트를 새로 구성하여 배포 실무에서 오프라인 분석이 용이하도록 보완했습니다.

### 2. 권한 및 집계 로직 (`permissions.ts`, `budgetAggregation.ts`)
- **집계 모델 강화:** 추후 '부서별/계정별 현황'에서도 공통으로 사용할 수 있도록 `aggregateByAccount` 및 `aggregateByDept` 가 단순 누적이 아닌, 월별(`monthlyDetails`) 내역을 보존하도록 개선했습니다. 또한 BudgetRow에 name fallback을 추가해 예산만 존재할 시에도 올바른 계정명을 표현하도록 보완했습니다.
- **권한 유틸 단일화:** 사용자의 부서(deptCode)가 아닌 `user.code` 기준으로 판단하도록 `getUserCode`, `getPermissionContext` 등을 통일했습니다. 
- **인건비 열람 권한 제어:** `user.code`가 `32100` (기획재무그룹) 또는 `99999` 인 경우, 혹은 관리자 패널에서 인건비 열람 권한을 직접 부여받은 경우에만 인건비 내역이 표시되도록 구조화했습니다.
- **기간 파싱 (parsePeriodMonth):** 'N월', '2026.01' 등의 문자열을 안전하게 인덱스로 매핑할 수 있도록 설계하였으며, 파싱 로직을 모든 업로드/분석 탭에서 재사용할 수 있도록 일원화했습니다.

### 3. 예산 작성 (`BudgetCreation.tsx`)
- **제출(Submission) 구조 편입 및 우회 방지:** 모든 부서가 제출/승인 완료된 상태에서 `isBudgetLocked` 일 경우 수정, 삭제, 초기화가 우회 조작되지 못하도록 차단했습니다. 제출 상태 저장 및 검사 로직을 전역 유틸리티로 관리(StorageKeys).

### 4. 실적 및 경영계획 데이터 업로드 (`PlanActualUpload.tsx`)
- **Validation Report View:** 사용자가 엑셀이나 텍스트를 붙여넣기 했을 시 무분별하게 업로드되지 않도록 `validationResult` 모달을 생성하여 오류 건과 경고 건을 요약해주고 잘못된 파싱 항목은 저장 제외되도록 했습니다. (오류: 부서 코드 형식, 빈 계정코드 등 / 경고: 수식 기반 잔액 계산 오류 등)
- **제출/승인 잠금 우회 방지:** 예산 계획 데이터로 업로드할 경우 대상 부서의 예산/계획이 현재 Locked 상태일 시 저장을 방지했습니다.

### 5. 업무활동경비 (`BusinessActivityBudget.tsx`)
- **수기 입력 행 보존 (sourceType 분리):** 무작정 같은 계정 코드를 가진 행을 갈아끼우던 문제를 해결하여, `BUSINESS_ACTIVITY_AUTO`라는 sourceType을 가진 Row들만 교체함으로써 사용자가 수동 작성한 잔여 행을 파괴하지 않게 했습니다.
- **반영 전 Preview:** 실제 적용 전에 업데이트될 대상 부서, 반영 금액, 갱신될 데이터 건수를 모달로 띄워 사용자가 최종 검토하도록 했습니다.
- **제출/승인 잠금 우회 방지:** 대상 부서가 Locked 상태일 땐 일괄 반영이 되지 않도록 락가드를 세웠습니다.

## 결론
이번 P0 안정화 패치로 모든 탭에서 실무상 데이터 오염 포인트가 차단되었으며, 특히 예산초과 점검 탭에서 디테일한 월별 추적이 가능해져 문제 기반 정리가 완료되었습니다. 이후 대시보드 고도화, 계정 및 부서별 현황 고도화를 위한 기반(집계 엔진 등)이 견고해졌습니다.
